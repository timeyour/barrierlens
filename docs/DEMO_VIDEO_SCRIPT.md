# BarrierLens Demo 视频脚本

目标时长：4:30 - 5:00

## 0:00 - 0:30 问题

画面：真实或可披露的盲道/入口受阻照片。

旁白：

> 很多无障碍问题不是没人看见，而是看见之后很难留下可跟进的证据。盲道被占、坡道被挡、通行链断点，单次反馈容易被忽略，问题也很难被汇总。

## 0:30 - 1:00 产品定位

画面：打开 BarrierLens 首页，展示故事线和三类场景。

旁白：

> 无碍 BarrierLens 是一个基于 Gemma 4 的公共空间无障碍通行风险识别与证据生成工具。人拍照不是为了让 AI 看见，而是为了让问题留下证据。Gemma 4 把现场照片转成结构化记录、风险地图和可导出的整改文本。

## 1:00 - 2:30 公众记录模式

画面：

1. 点击“开始记录”。
2. 使用样例图或上传现场照片。
3. 选择公众记录，填写地点。
4. 点击生成。
5. 展示结构化结果、Barrier Map、证据要点。
6. 复制或导出公众倡导摘要。

旁白：

> 第一条链路是公众记录。普通人只需要上传照片，系统会识别问题类型、风险等级、受阻路径和影响人群。结果会自动归档到本地时间线，也可以导出给公益组织、媒体或社区沟通使用。

## 2:30 - 3:30 物业自查与复查

画面：

1. 切换到物业自查。
2. 再次生成巡查整改单。
3. 打开时间线。
4. 修改状态为已反馈/待复查。
5. 上传整改后复拍照片。
6. 展示前后对比和整改状态。

旁白：

> 第二条链路是物业自查。对于物业、商场或园区，系统会生成内部巡查整改单。整改后可以上传复拍照片，形成前后对比，状态也能从待处理推进到待复查或已整改。

## 3:30 - 4:30 Gemma 4 证明链

画面：

1. 生成分析后，**暂停在结果页绿色 banner**（应显示 `analysisSource=gemma` 与模型名）。
2. DevTools → Network → `/api/analyze` → Response（`analysisSource`、`model`、`mockMode: false`）。
3. 展开「开发者 · Gemma JSON」面板。
4. 切到 GitHub：`src/lib/gemma.ts` → `src/app/api/analyze/route.ts`。
5. 展示 `docs/MODEL_PROVENANCE.md`（未微调声明）。

旁白：

> 证明 Gemma 4 有三层：接口返回 `analysisSource=gemma` 和模型 ID；页面 banner 明确标注来源；代码在 `gemma.ts` 调用 Google REST，未微调，只靠 Prompt 和 JSON 约束。若看到 `mock` 或 `mock_fallback`，那是演示降级，不代表真实 Gemma 识图能力。

## 4:30 - 5:00 展望

画面：时间线多条记录、三类场景、技术报告结尾。

旁白：

> BarrierLens 的第一版不做大平台、不做执法系统，而是先把记录和证据链跑通。下一步可以扩展更多设施类型、更多真实点位，并和公益组织、物业或社区做实地验证，让无障碍问题被看见、被记录、被复查。

## 录制检查清单

- 全程只打开 **https://barrierlens-1utx.vercel.app/#tool**（与 README 在线 Demo 一致）。
- 桌面端录制一遍公众记录。
- 桌面端录制一遍物业自查与复查。
- 移动端截图或短片展示响应式可用。
- 如果使用 Mock，口播和画面必须明确说明。
- 视频时长不要超过 5 分钟。
